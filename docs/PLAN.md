## S5 编码与数据管线
- 使用 obs v6，1014×34 输入、34 个牌 token 加 CLS、46 维合法动作空间。
- 文件级打乱之外，增加每个 worker 65,536 样本的跨文件流式混合缓冲；被选样本保留一次，尾部缓冲完整排出。后续增加每局每位玩家最多 64 个随机决策的训练采样上限，扩大同一计算预算覆盖的对局数；验证集不采样裁剪。
- SL-A 使用 8 个 worker、每次解码 4 个文件、预取 2 个 batch。
- 检查标准：无样本丢失/重复、失败文件不引起标签错配、内存低于容器配额、吞吐满足训练。

## S7 监督学习 [汇报]
- 阶段 A：王座 2023/2024 + 玉之间 2019 半庄，已从 36,000 步续训，46,000 步启用单局采样上限；11:01 已达 58,200 步；目标 300,000 步。
- 采用跨文件混合与单局采样上限；每 2,000 步保存并验证，关注辅助头泛化和动作准确率。连续 3 次验证 rank >1.9 或 value >1.7 时停止并保留断点，避免继续消耗预算。
- 短对照试验：同一断点各更新 300 步，混合版验证 rank/value 为 1.324/1.379，原方案为 1.528/1.594；后续至 46,000 步的验证显示辅助头仍回升，因此改为每玩家每局最多 64 个决策；该方案 1,000 步试验 rank 从 1.689 降至 1.311、value 从 1.417 降至 1.342，动作准确率从 77.98% 到 77.73%。继续以长训验证判断泛化趋势。
- 阶段 B 可选：新玉之间半庄索引审核后，以较小学习率微调；是否采用及预算由阶段 A 评估决定。
- 检查标准：验证指标与 S8 对战结果；阶段 A 完成先汇报，流水线默认停在审核节点。

## S8 对战评估 [汇报]

- 目标指标：平均顺位、玉之间完整期望段位分、四位率、和牌率、放铳率、立直率、副露率。
- 评估已补齐完整段位分 mean_pt（含素点）、按牌山 seed 聚类的标准误和每 seed 结果，保留 pt_placement 作为分项。2026-11-10 19:40 已补齐挑战者每局的和牌/自摸/放铳/立直/副露率（eval 输出 `style` 字段）；正式验收使用独立保留 seeds，不能仅看训练中重复使用的选优 seeds。

## S9 强化学习 [定期汇报]
- 半庄自我对弈，PPO + SL 策略 KL 约束、历史对手池。回报默认为 GRP 按局奖励（`return_mode=grp`，见 rules.md），半庄 GRP 已训练（`ckpt/grp_hanchan.pth`，验证 CE 1.125）；完整终局段位分回报 `terminal` 保留为可选对照。
- PPO 在一轮更新前冻结旧策略概率与价值基线，优势估计跨 epoch 固定；尾批保留，检查损失及梯度有限性。
- 小模型生成→更新→保存加载→评估端到端测试通过；生产架构 1,013 样本、mb=1024 更新通过，PyTorch allocated 峰值约 8.64GiB。完整 250 seeds/轮的主存峰值仍须测量，再按预算启动长期 RL。
- 选优按完整 mean_pt，初始 SL 也参与 best 比较；每次与历史最佳使用相同 seeds 的配对差值。连续 3 次未超过差值标准误的 2 倍则停止，此为预算启发式，不是经过多重比较校正的显著性结论。
